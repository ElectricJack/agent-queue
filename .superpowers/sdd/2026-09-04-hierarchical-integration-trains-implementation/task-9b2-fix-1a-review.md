## Finding Verdicts

1. **The generic candidate observer can consume a `root_main` claim without advancing its root intent, permanently stranding a successfully pushed promotion.** — **ADDRESSED.** Candidate reconciliation now has a closed candidate-purpose set and treats every other unresolved purpose, including `root_main`, as a blocker without observing or mutating it (`src/integration/candidates.py:39-45`, `src/integration/candidates.py:2184-2185`, `src/integration/candidates.py:2245-2247`). Root reconciliation no longer returns early for an already-applied claim: `_mark_applied` validates the root claim and advances a still-prepared intent to pushed in the same hierarchy transaction (`src/integration/main_promotion.py:569-620`). The cross-service regression leaves the root claim reserved through public candidate build/rebuild and then proves fresh root reconciliation finalizes with one push (`tests/test_integration_main_promotion.py:780-827`).

2. **A prewrite-marked ambiguous claim is CAS-taken and blindly pushed after expiry.** — **NOT ADDRESSED.** The ambiguity/takeover half is corrected: both owned renewal and expired CAS require `prewrite_at IS NULL`, and any marked unresolved claim is blocked before takeover (`src/integration/main_promotion.py:393-394`, `src/integration/main_promotion.py:490-529`). The required execution horizon is still insufficient, however. `_mark_prewrite` requires only `120 + 5` seconds of remaining lease/claim authority (`src/integration/main_promotion.py:39-41`, `src/integration/main_promotion.py:531-567`), but after setting the irreversible ambiguity marker the service performs a separately bounded local Git ancestry operation and only then acquires the installation token before starting the 120-second authenticated push (`src/integration/main_promotion.py:437-454`, `src/integration/main_promotion.py:943-959`; `src/git/manager.py:338`, `src/git/manager.py:4092-4119`). Token acquisition is not guaranteed to be a cache hit: a cached token is reused only while it has more than 300 seconds remaining, while refresh performs three independently 30-second HTTP requests (`src/git/github_app.py:109`, `src/git/github_app.py:194-249`). Thus the project lease and execution claim can expire before the actual main write starts, yet the service still pushes. This violates the fix brief's fresh horizon through the full bounded Git operation and the final-authority-through-write invariant. Move the local fast-forward proof and installation-token acquisition before the final hierarchy-locked `_mark_prewrite` revalidation, leaving only the bounded push after the marker, or size and enforce the horizon for every bounded operation that remains after it. Add a clock-advancing local-Git/token-refresh regression proving an expired lease/claim cannot reach `apush_oid_with_app_auth`; the current horizon test merely advances time before reconcile and asserts a 135-second claim (`tests/test_integration_main_promotion.py:651-675`).

3. **External movement of main leaves the current root intent permanently blocking the required N+1 rebuild.** — **ADDRESSED.** A live exact claim waits, while an expired, exact-nonce, prewrite-null current claim is superseded with the intent and batch lifecycle in one hierarchy transaction (`src/integration/main_promotion.py:410-421`, `src/integration/main_promotion.py:622-702`). The regression uses public `CandidateService.rebuild`, creates revision N+1, and verifies preserved members and structured repair subject without directly changing `current_revision` (`tests/test_integration_main_promotion.py:874-947`).

4. **Authenticated descendant reconciliation has no authenticated object import, so normal production history cannot prove ancestry.** — **ADDRESSED.** A non-expected/non-candidate remote OID is fetched through the Task 9a App-auth exact-OID primitive into an intent-specific recovery ref before local ancestry proof; mismatched import or indeterminate ancestry blocks (`src/integration/main_promotion.py:375-384`, `src/integration/main_promotion.py:943-973`). The real-Git regression begins with the descendant absent locally, imports the exact OID, and proves the retained ref and ancestry (`tests/test_integration_main_promotion.py:1002-1075`).

5. **Required immutable pre-main attestation proof cannot be bypassed by direct service or command invocation.** — **ADDRESSED.** Strict frozen subject/proof models bind repository numeric/full identity, operation, batch, revision, candidate SHA, check version, check-run ID, and canonical external ID (`src/integration/main_promotion.py:70-98`). Prepare resolves the server-owned proof before pinning or reservation and freezes it in immutable intent provenance, while reconcile re-resolves it before claim and the prewrite transaction compares it against locked current state (`src/integration/main_promotion.py:147-166`, `src/integration/main_promotion.py:223-230`, `src/integration/main_promotion.py:423-437`, `src/integration/main_promotion.py:531-567`).
