First tagged release of Agent Queue. It covers everything that reached `dev`
after the pre-takeover `main` baseline (`259c0f56`) up to `73509417`. The task
ids in brackets are the note sources listed above; short SHAs name commits that
landed without a task of their own.

### Added

Release and promotion:

- A `dev` → `staging` → `main` promotion flow. `aq promote prepare` files the
  version-and-notes task with immutable notes input; `aq promote request`,
  `approve` and `cancel` gate one pinned commit; request admission rechecks the
  notes' source digest (vivid-stone-39.2).
- `aq promote rulesets` and `aq promote validate --remote` derive branch and tag
  rulesets and workflow triggers, and report remote protection gaps as warnings
  (vivid-stone-39.1).
- Gated hotfix promotions with back-merge sources, and reviewed promotion
  policies with a two-step proof (c97455bf4, 74a96b63d).
- Release-tag protection for `v*`, and a trust manifest and GitHub activation
  plan for the three branches (0d275a536, 17a6ac7f6).
- Default-branch cutover tooling: `aq integration cutover-plan` (read-only) and
  `aq integration cutover` (local preview, apply and `--reverse`). Both use a
  saved-preview fence, a root barrier and audited receipts (wise-ember-69.1,
  wise-ember-69).

Git and branch hygiene:

- When a task lands, its branch is deleted on settle once ancestry proves it
  reached the target. This applies to every registered AQ checkout of the
  repository; live, busy, dirty or moved work is kept (fleet-ridge-45.2).
- Abandoned, cancelled, failed, superseded and aborted branches are retired
  with a durable pre-delete SHA audit. Project branch backlogs are swept and
  reported to each project's supervisor (fleet-ridge-45.3, 2f7b942ba).
- Completion and replacement provenance moved out of branch refs into
  `refs/aq/provenance`. `aq integration migrate-provenance-refs` moves an
  existing repository's refs and dry-runs by default (fleet-ridge-45.5).
- A stopped writer's WIP is saved onto its own task branch, and the next worker
  resumes there. This covers provider failover, `aq task stop` and usage limits;
  no `aq/preserved` copies are made (fleet-ridge-45.1, 030358252, 557438f00).
- Work delivered outside AQ can be recorded with exact Git provenance
  (580966222).

Routing, sessions and scheduling:

- Risk-aware default-assignment routing. A missing or failed risk answer counts
  as medium risk (solid-apex-59, drafted in smart-beacon-29).
- Agent cron: `aq cron register`, `show`, `list` and `cancel` schedule durable,
  session-owned recurring prompts (49a6e9c1f).
- `aq session cleanup [--dry-run] [--project-id]` stops and prunes taskless
  sleeping named sessions (6170a70fc).

Projects and policy:

- Portable policy profiles: `aq policy export`, `diff` and `apply`, with
  selective reviewed imports and a dashboard page (8795562fa).
- New projects are created with audited repository authorization, and an
  existing initialized project can take an audited repository binding
  (e5a6b120a, solid-delta-97).

Dashboard:

- Graph UI phase A: design tokens, a light palette and live theme switching
  (eager-bridge-32.1); card and frame anatomy with status pills, stripes and a
  legend (eager-bridge-32.2).
- Agent terminals on phones attach like the desktop ones. Every viewport keeps
  the host shell's font, palette and scrollback (keen-meadow-54, ee48bf226).

### Changed

- Source work lands on `dev`; `staging` and `main` are reached only by
  promotion (6097e179a, docs/config/agent-queue-promotion-flow.yaml).
- Hand landing (`aq git pr-merge`) and operator tools merge the original
  branch instead of squashing, rebasing or cherry-picking it; `pr_merge`
  defaults to `merge` (fleet-ridge-45.4).
- Durable message delivery no longer waits on scheduler work (10bae4acf).
- Integration train selection is bounded and reports operation metrics
  (0290e8ee2).
- Before cutover, idle train admission can be quiesced locally under a fence.
  Historical parked publisher records are retired through the supported sweep
  (1aeaaa026, e4848093d, b6c82b36d).
- Expired integration mutations are reconciled by a fenced remote read-back
  (c07c8076a).
- Agents are pointed at canonical knowledge records (6abacfa67).
- A regression suite for the integration train's overnight failures
  (vivid-orbit-95), and cleanup of leftover integration refs on origin that now
  covers epic, preserved and repair refs (nimble-current-27).
- New promotion-flow and releases guides (vivid-stone-39.6).
- Git-first train policies can omit the legacy playbook route; integration
  uses the configured train runtime (202a15d4a).

### Fixed

- Supervisor API credentials renew during long sessions and can be re-minted
  with their existing scope. The stall sweep reports one actionable
  authentication finding (sharp-quest-52).
- Spec-ingest and other no-code roles can close without being forced through
  branch delivery provenance (quick-flare-87).
- Epic and phase activity is derived from descendants, so an idle container
  no longer displays running stripes just because its stored lifecycle is
  `IN_PROGRESS` (bright-nexus-99).
- Invalid promotion intents produce a visible hold and a doctor finding with
  an `aq promote repair` command. The operator or supervisor can repair them
  after a task-row backup (solid-impact-50).
- Morning reports are triggered once per local day, instead of creating a new
  playbook run every minute (quick-impact-41).
- Paused projects hold human escalation and review notifications. Review
  requests decided or withdrawn while paused are retired before delivery
  resumes (prime-stone-95).
- Continuous promotion policies receive their events through the Git-first
  service's durable outbox. Lagging steps appear in doctor and stall-sweep
  findings (prime-glacier-38).
- Projects left on the retired `development` integration mode never
  delivered. Trust-manifest bootstrap now accepts a bound development policy
  and explains missing hosted CI trust (fleet-quest-31, bright-impact-83,
  prime-current-26).
- Exporting a legacy playbook policy failed with a raw 422. Sources are now
  recovered and backfilled, and a doctor check reports any gaps
  (swift-apex-86).
- A withdrawn review left its gate open. Withdrawal now cancels the gate and
  records who withdrew it (grand-delta-18).
- Supervisor nudges pointed at messages that other projects had addressed to
  its mailboxes, which it could not read (clear-zenith-84). A worker can now
  re-read bodies its own `--inject` consumed (78b8e4a04).
- The dashboard listed Codex pool workers as "Outside pool"
  (bright-beacon-79).
- `aq promote request` refused a green `dev` tip with `promotion_source_red`
  (azure-impact-28), and `--step staging` failed with "invalid expected target
  OID" (clear-ember-42).
- A superseded or failed source-CI repair could be sealed into a batch and hold
  the lane (prime-pinnacle-81).
- Stacked branches could silently lose content when batched; named blockers now
  stop the batch (stark-grove-47).
- The release-notes range honours the first-release bootstrap bound and is
  bounded for steps without a version; notes are skipped when `notes.kind` is
  `none` (vivid-stone-39.7).
- Cutover preserves materialized origins and accepts both receipt spellings
  (wise-ember-69.5).
- The stall-sweep patrol confused a healthy empty queue with a failed read,
  did not isolate projects sharing a patrol, and repeated its bare-repository
  branch backstop (stark-pinnacle-12, eager-grove-47).
- Branch retirement rejected authenticated repository URLs (bright-flare-68).
- e2e flakes: S19 raced the scheduler, and the S1 and S16b fixtures did not
  retry a transient empty claim (wise-stone-59, crisp-flare-89,
  azure-vault-24).
- Completed leaf roots whose PR checks failed are reopened to their worker
  (fc86b2059). COMPLETED tasks are reconciled with delivery (0f13d7ef3), and
  closed task PRs are reopened while live work is protected from cleanup
  (6b39710ed).
- An approved spec's ingest batch now applies in the proposing transaction
  instead of waiting in `ready` (37a2b7843).
- Worker context-thrash relaunch loops (c8f5e69b6), isolated Git processes
  interrupted during startup (69b91e1a3), and missed OpenCode retry footers
  with right-aligned chrome (46cb937f7).
- Promotion tasks stay in progress across a daemon restart and are never
  routed (4274a6c5f).
- Source-CI repairs that only touched ownership inventories, fingerprints and
  test ratchets: grand-ember-22, vivid-delta-43, brisk-ridge-22, crisp-ridge-54,
  wise-rapids-99, solid-journey-58 and sharp-orbit-80.

### Upgrade

This release adds five Alembic revisions, `a00000000086` to `a00000000090`.
The operator applies them with `aq db upgrade` after deploying; workers never
migrate.

- `086_default_branch_cutover`: records the default-branch cutover without
  rewriting materialized origins.
- `087_agent_cron`: session-owned recurring prompts.
- `088_branch_deletion_audit`: records every abandoned branch before its ref is
  deleted.
- `089_branch_retirements`: explicit branch retirement and the pre-delete SHA
  audit.
- `090_review_withdrawal_recovery`: adds nullable withdrawal-audit columns to
  `doc_reviews` and widens `ck_gates_status` to admit `cancelled`. It also
  backfills existing withdrawn reviews: their gates become `cancelled` and the
  affected tasks get `needs_attention`.

`python scripts/check_additive_migrations.py --from-ref 259c0f56ecf9a9d9e3c0a18d31df9b67264eea3f --to-ref 73509417ffeb31c197ac7419d3aa5491d196eec6 --json`
passes 086–089 and reports four findings, all in 090: three data `execute`
calls (lines 28, 47 and 55) and the `drop_constraint` that recreates
`ck_gates_status` (line 41).

Existing repositories may move provenance with
`aq integration migrate-provenance-refs <project>` (dry run), then `--apply`.
Legacy provenance reads keep working without it.

### Breaking

- Task priority no longer affects routing. No lane or local-model rule reads
  it, and the `high_priority_local_model` stall check is gone (solid-apex-59).
- `pr_merge` defaults to `merge`; pass the `squash` method explicitly to keep
  the old behaviour (fleet-ridge-45.4).
- The checker cannot prove migration 090 additive (see Upgrade). Treat a
  rollback below 0.1.0 after upgrading as a database restore (`aq db restore`),
  not `aq update --allow-rollback`.
