Release preparation for Agent Queue 0.1.1. The frozen input has no previous
matching release tag, so these notes cover the full first-release range from
`259c0f56` through `c0756547`, including work already described in the
[0.1.0 preparation notes](0.1.0.md). Task ids identify the sources in frontmatter;
short SHAs identify commits without a task source. Preparation does not prove
promotion, tagging or deployment.

### Added

- Playbooks install once into a fresh vault using an external receipt. Restart
  observes existing state instead of restoring deleted, disabled or stale
  policy; explicit doctor repair handles missing required state. New-project
  creation and onboarding offer default, exported or no policy. Existing
  projects and activations are preserved (noble-cascade-85, calm-vault-68,
  calm-vault-68.1, calm-vault-68.2, calm-vault-68.3).
- The dashboard lists project supervisors and lets operators message them
  (9049eb992).
- Portable setup exports include their complete policy dependencies (6144e8419).

Release and promotion:

- A `dev` → `staging` → `main` promotion flow. `aq promote prepare` files the
  version-and-notes task with immutable notes input; `aq promote request`,
  `approve` and `cancel` gate one pinned commit; request admission rechecks the
  notes' source digest (vivid-stone-39.2).
- `aq promote rulesets` and `aq promote validate --remote` derive branch and tag
  rulesets and workflow triggers, and report remote protection gaps as warnings
  (vivid-stone-39.1).
- Gated hotfix promotions with back-merge sources, and reviewed promotion
  policies with a two-step proof (c97455bf4, 74a96b63d).
- Release-tag protection for `v*`, and a trust manifest and GitHub activation
  plan for the three branches (0d275a536, 17a6ac7f6).
- Default-branch cutover tooling: `aq integration cutover-plan` (read-only) and
  `aq integration cutover` (local preview, apply and `--reverse`). Both use a
  saved-preview fence, a root barrier and audited receipts (wise-ember-69.1,
  wise-ember-69).

Git and branch hygiene:

- When a task lands, its branch is deleted on settle once ancestry proves it
  reached the target. This applies to every registered AQ checkout of the
  repository; live, busy, dirty or moved work is kept (fleet-ridge-45.2).
- Abandoned, cancelled, failed, superseded and aborted branches are retired
  with a durable pre-delete SHA audit. Project branch backlogs are swept and
  reported to each project's supervisor (fleet-ridge-45.3, 2f7b942ba).
- Completion and replacement provenance moved out of branch refs into
  `refs/aq/provenance`. `aq integration migrate-provenance-refs` moves an
  existing repository's refs and dry-runs by default (fleet-ridge-45.5).
- A stopped writer's WIP is saved onto its own task branch, and the next worker
  resumes there. This covers provider failover, `aq task stop` and usage limits;
  no `aq/preserved` copies are made (fleet-ridge-45.1, 030358252, 557438f00).
- Work delivered outside AQ can be recorded with exact Git provenance
  (580966222).

Routing, sessions and scheduling:

- Risk-aware default-assignment routing. A missing or failed risk answer counts
  as medium risk (solid-apex-59, drafted in smart-beacon-29).
- Agent cron: `aq cron register`, `show`, `list` and `cancel` schedule durable,
  session-owned recurring prompts (49a6e9c1f).
- `aq session cleanup [--dry-run] [--project-id]` stops and prunes taskless
  sleeping named sessions (6170a70fc).

Projects and policy:

- Portable policy profiles: `aq policy export`, `diff` and `apply`, with
  selective reviewed imports and a dashboard page (8795562fa).
- New projects are created with audited repository authorization, and an
  existing initialized project can take an audited repository binding
  (e5a6b120a, solid-delta-97).

Dashboard:

- Graph UI phase A: design tokens, a light palette and live theme switching
  (eager-bridge-32.1); card and frame anatomy with status pills, stripes and a
  legend (eager-bridge-32.2).
- Agent terminals on phones attach like the desktop ones. Every viewport keeps
  the host shell's font, palette and scrollback (keen-meadow-54, ee48bf226).

### Changed

- Project supervisors now require explicit opt-in, including on existing
  projects. Projects with supervisors disabled route supervisor work globally
  (1c9335a2e).
- Bugfixes escalate to a higher intelligence class after failed standard
  attempts (cc0283d2c).
- Generated repair instructions come from live vault templates, and source-CI
  repair workers run focused checks while CI owns the broad sweep (f64b31c5e,
  859e30e68).
- Repeated pool claim refusals receive durable backoff, and repeated identical
  preparation failures quarantine the workspace with a single supervisor report
  (358ab4eb9).

- Source work lands on `dev`; `staging` and `main` are reached only by
  promotion (6097e179a, docs/config/agent-queue-promotion-flow.yaml).
- Hand landing (`aq git pr-merge`) and operator tools merge the original
  branch instead of squashing, rebasing or cherry-picking it; `pr_merge`
  defaults to `merge` (fleet-ridge-45.4).
- Durable message delivery no longer waits on scheduler work (10bae4acf).
- Integration train selection is bounded and reports operation metrics
  (0290e8ee2).
- Before cutover, idle train admission can be quiesced locally under a fence.
  Historical parked publisher records are retired through the supported sweep
  (1aeaaa026, e4848093d, b6c82b36d).
- Expired integration mutations are reconciled by a fenced remote read-back
  (c07c8076a).
- Agents are pointed at canonical knowledge records (6abacfa67).
- A regression suite for the integration train's overnight failures
  (vivid-orbit-95), and cleanup of leftover integration refs on origin that now
  covers epic, preserved and repair refs (nimble-current-27).
- New promotion-flow and releases guides (vivid-stone-39.6).
- Git-first train policies can omit the legacy playbook route; integration
  uses the configured train runtime (202a15d4a).

### Fixed

- Explicit named-session sleep requests are carried out independently of idle
  timeout. Sleep cancels recurring prompts; failed stops retry without losing
  concurrent wake requests (prime-falcon-87, 5ec3e977c).
- Nudging a message leaves it pending until the recipient reads the body;
  notification attempts and delivery receipts are separate (428e89a53).
- Provider notices deduplicate across supervisor routing changes, and provider
  lookup works across merged named-session paths (0ad587cd9, f826cb7a7).
- Operator pools start with the correct role, and routing diagnostics distinguish
  a missing compiled operator rule (steady-summit-55).
- Task deletion no longer deadlocks against blocked-state projection refresh:
  refresh locks task snapshots in ID order with `FOR NO KEY UPDATE` and updates
  only the captured rows (bold-current-10).
- Failed-close cleanup retains the published task tip until strict handoff
  verification and detach; restart refusals name supervisor release-owner
  recovery (bold-stone-34).
- Running task-card stripes loop seamlessly while preserving static and
  reduced-motion behavior (brisk-bridge-16).
- Unified deletion contracts, source-CI ownership inventories, recovery assertions
  and migration chaining were reconciled without weakening budgets or guards
  (azure-apex-41, amber-pinnacle-53, calm-beacon-11, prime-torrent-82,
  crisp-stone-67; 01df2198a, 4966fec23, 0a820eb0e, 388674618, 62a6e6eaa,
  f5f00bb98, 9bc546262, be272cc77, 95c8c4315, f56b6a92c, 08c107d4b,
  0d33d00e4).

- Supervisor API credentials renew during long sessions and can be re-minted
  with their existing scope. The stall sweep reports one actionable
  authentication finding (sharp-quest-52).
- Spec-ingest and other no-code roles can close without being forced through
  branch delivery provenance (quick-flare-87).
- Epic and phase activity is derived from descendants, so an idle container
  no longer displays running stripes just because its stored lifecycle is
  `IN_PROGRESS` (bright-nexus-99).
- Invalid promotion intents produce a visible hold and a doctor finding with

  after a task-row backup (solid-impact-50).
- Morning reports are triggered once per local day, instead of creating a new

  resumes (prime-stone-95).

### Upgrade

The cumulative range contains nine Alembic revisions, `a00000000086` through
`a00000000094`. Operators apply upgrades after deployment; workers never migrate.

- 086 records the default-branch cutover without rewriting materialized origins.
- 087 adds session-owned recurring prompts.
- 088 and 089 add branch deletion/retirement audits with exact pre-delete SHAs.
- 090 records review withdrawal, cancels withdrawn gates and marks affected tasks
  for attention.
- 091 persists identical claim-preparation refusal counts and reasons.
- 092 separates notification attempts from message delivery receipts and reopens
  legacy nudged mail whose body was neither read nor archived.
- 093 persists pool claim-refusal backoff across daemon restarts.
- 094 adds `projects.supervisor_enabled`, defaulting to false even for existing
  projects. Explicitly enable each project supervisor that should run.

The additive-migration checker reports **six non-additive or unproven findings**
at the frozen source: migration 090 has `execute` at lines 28, 47 and 55 and
`drop_constraint` at line 41; migration 091's loop-based `add_column` at line 24
lacks a literal `Column` declaration the checker can prove; migration 092 has
`execute` at line 27. The other six revisions pass the static audit.
These are existing source findings, preserved by this preparation.
Request-time admission can refuse `migrations_not_additive`; resolve that gate
through the supported release process before publishing a tag.

  --from-ref 259c0f56ecf9a9d9e3c0a18d31df9b67264eea3f \

`aq integration migrate-provenance-refs <project>` (dry run), then `--apply`.

### Breaking

- Project supervisors are off until explicitly enabled, including existing
  projects (migration 094, 1c9335a2e).
- Task priority no longer affects routing (solid-apex-59).
- `pr_merge` defaults to `merge`; pass `squash` explicitly for the old behavior
  (fleet-ridge-45.4).

  needs explicit repair instead of an automatic reinstall (noble-cascade-85).
- Additive rollback safety is unproven for revisions 090–092. Database restore
  (`aq db restore`) remains a separate recovery action from code rollback.
