# Development setup

Getting a checkout of Agent Queue to the point where you can change a module
and run its tests.

## Why this page exists

AQ has three installable pieces (the Python package, the generated Python API
client, and an npm workspace holding the dashboard and its TypeScript client)
and one external dependency it cannot fake (PostgreSQL). Setting them up in
the wrong order produces confusing errors — a test suite that reports
`POSTGRES_TEST_DSN is not set`, a dashboard that will not start because the
generated client is missing. This page puts them in an order that works.

You do **not** need a running daemon to develop AQ. Almost every check in
[local checks](checks.md) runs against a throwaway database the test harness
creates for itself.

## Vocabulary

* **Editable install** — `pip install -e`, so the package on `sys.path` is your
  checkout rather than a copy. AQ is always installed this way in development.
* **Extra** — an optional dependency group declared in
  [`pyproject.toml`](../../pyproject.toml), selected as `".[dev,cli]"`.
* **npm workspace** — the root [`package.json`](../../package.json) owns two
  workspaces, `packages/aq-ts-client` and `dashboard`; one `npm install` at the
  repository root installs both.
* **Data directory** — `~/.agent-queue/`, where an *operator's* daemon keeps
  its config, vault and logs. A contributor's checkout normally does not write
  there. See the [glossary](../reference/glossary.md).

## Prerequisites

| Requirement | Why | Checked by |
|---|---|---|
| Python 3.12 or newer | `requires-python = ">=3.12"` in [`pyproject.toml`](../../pyproject.toml); the code uses 3.12 syntax and ruff targets `py312`. | `python3 --version` |
| PostgreSQL | The only supported backend. The suite builds throwaway databases in it. | `docker compose ps` |
| Git | Worktrees, branches and the integration path. | `git --version` |
| Node.js and npm | Only if you touch the dashboard or the TypeScript client. | `npm --version` |
| `tmux` | Only if you run tests marked `tmux`, or a real agent session. | `tmux -V` |

SQLite is **not** a supported backend. It was removed; a compatibility extra
(`sqlite-import`) exists solely for the one-way `aq db import-sqlite` importer.

## Install

```bash
git clone <your fork or the canonical remote> agent-queue
cd agent-queue
python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev,cli]"
pip install -e packages/aq-client
```

```text
Successfully installed agent-queue-0.1.0
Successfully installed agent-queue-api-client-0.1.0
```

`[dev]` brings pytest, `pytest-asyncio`, `pytest-xdist`, `ruff`, `pre-commit`
and the **exactly pinned** `openapi-python-client` the committed API client was
generated by — see [code generation](codegen.md#the-python-api-client).
`[cli]` brings `click`, `prompt-toolkit` and the generated client the `aq`
command dispatches through.

Other extras exist for provider SDKs (`anthropic`, `google`, `openai`, or `llm`
for all three), the MCP server (`mcp`), Google inbox integration (`inbox`) and
the MkDocs toolchain (`docs`). Install them only if you are working on that
area. `postgresql` is an empty compatibility extra retained so an older
`pip install -e ".[dev,cli,postgresql]"` keeps working; `asyncpg` is a core
dependency now.

> **Note.** [`setup.sh`](../../setup.sh) automates the same steps and will try
> to install Python, Node and npm packages for you, prompting for `sudo`. It is
> convenient on a fresh machine and is what an *operator* runs, but it is not
> the contributor path and it carries two stale steps (it requests a `gemini`
> extra that `pyproject.toml` does not define, and installs `acpx`, a retired
> runtime). Prefer the explicit commands above. [`uninstall.sh`](../../uninstall.sh)
> is its counterpart and returns the checkout to a fresh-clone state; it can
> also remove `~/.agent-queue/`, so read its `--help` before running it.

## PostgreSQL for tests

The repository ships a disposable service in
[`docker-compose.yml`](../../docker-compose.yml): PostgreSQL 18 on host port
**5533**, database/user/password `agent_queue` / `agent_queue` /
`agent_queue_dev`, with its data in a named volume.

```bash
docker compose up -d postgres
export POSTGRES_TEST_DSN=postgresql+asyncpg://agent_queue:agent_queue_dev@localhost:5533/postgres
```

```bash
aq test tests/test_config.py
```

```text
aq test: slot 0 of 2, -n 3
$ .../python -m pytest -n 3 --dist loadfile -m 'not perf and not …' tests/test_config.py
```

Put the `export` in your shell profile or an `.envrc`; every test run needs it,
and [`tests/conftest.py`](../../tests/conftest.py) fails the whole session at
setup when it is missing rather than producing hundreds of fixture errors.

Point `POSTGRES_TEST_DSN` at a *maintenance* database (`postgres` above), not
at a database you care about: the harness creates and drops databases beneath
it. It never touches the daemon's database — see below.

Cleanup, when you want the disk back:

```bash
docker compose down -v          # stops the service and deletes the volume
```

### Never migrate the operator's database

`~/.agent-queue/config.yaml` names a *running system's* database. Migrating it
is a daemon-only operation.

Inside an AQ worktree slot the environment carries `AQ_DB_SCOPE=worker` and
sentinel values for `AQ_DATABASE_URL` / `AGENT_QUEUE_DB`; the CLI refuses to
migrate from that scope, and
[`src/database/migration_guard.py`](../../src/database/migration_guard.py)
refuses at the engine. [`tests/conftest.py`](../../tests/conftest.py) adds an
outer fence: if any of `POSTGRES_TEST_DSN`, `AGENT_QUEUE_DB` or
`AQ_DATABASE_URL` addresses the production database, collection fails before a
single test runs.

If you see **"schema behind code; ask the operator to upgrade"**, that is the
guard working. Report it; do not work around it. `aq db current` is the
read-only "am I behind?" answer and is always safe. The full rules are in
[migrations](../guides/migrations.md).

## Node and the dashboard

```bash
npm install                                    # installs both workspaces
./scripts/regenerate-ts-client.sh --from-file  # writes packages/aq-ts-client/src/
npm run build                                  # tsc -b && vite build
```

The TypeScript client's `src/` is **gitignored and generated on demand** from
the committed [`openapi.json`](../../openapi.json), so a fresh checkout has to
generate it once before the dashboard will type-check or build.
`dashboard/package.json` wires this in as a `pre` script, so `npm -w dashboard
run dev` regenerates it for you; the explicit command above is what to run when
you want the error message rather than the surprise.

Root scripts, from [`package.json`](../../package.json):

| Command | Does |
|---|---|
| `npm run dev` | Vite dev server for the dashboard. |
| `npm run build` | Builds the TS client (a no-op — it is consumed as source) then the dashboard. |
| `npm run lint` | ESLint over `dashboard/`. |
| `npm run typecheck` | `tsc -b --noEmit` over `dashboard/`. |
| `npm run generate` | Regenerates both API clients — see [code generation](codegen.md). |

Dashboard unit tests are Vitest: `npm -w dashboard run test`.

## Editor and agent configuration

| File | What it configures |
|---|---|
| [`.pre-commit-config.yaml`](../../.pre-commit-config.yaml) | Two hooks, both `ruff` (`ruff-format`, then `ruff --fix`). Enable with `pre-commit install`. |
| [`.mcp.json`](../../.mcp.json) | Offers a single MCP server, `agent-queue`, over HTTP at `localhost:8082/mcp`, to MCP-aware editors and agent CLIs working in this repository. Only useful with a daemon running. |
| [`.vibecop.yml`](../../.vibecop.yml) | Ignore list for the `aq-vibecop` plugin's scans: generated clients, `docs/`, `scripts/` and vendored trees. |
| [`.gitattributes`](../../.gitattributes) | Forces LF line endings for `*.sh`, `*.py` and, by default, every text file — the repository is developed on Linux, macOS and WSL. |
| [`.gitignore`](../../.gitignore) | Keeps build output, `node_modules/`, the generated TS client source, per-checkout `/.aq/` agent state, coverage output and local logs out of Git. |

Ruff's own settings live in [`pyproject.toml`](../../pyproject.toml):
line length 100, target `py312`, `packages/aq-client` excluded because it is
generated.

## Inputs and outputs

| You provide | AQ produces | Where it lives |
|---|---|---|
| A Python 3.12+ interpreter | An editable `agent-queue` install and the `aq`, `agent-queue` entry points | your virtualenv |
| A PostgreSQL server and `POSTGRES_TEST_DSN` | Per-worker template and lease databases | that server, dropped on teardown |
| `npm install` | `node_modules/`, and (on demand) `packages/aq-ts-client/src/` | the checkout, gitignored |
| Nothing | `.pytest_cache/`, `.ruff_cache/`, `__pycache__/`, `/.aq/` | the checkout, gitignored |

## State ownership

* **Your checkout** owns source, the committed generated artefacts
  ([codegen](codegen.md)) and nothing else.
* **The test harness** owns every database it creates under
  `POSTGRES_TEST_DSN`, and removes them on teardown
  ([`tests/db_fixtures.py`](../../tests/db_fixtures.py)).
* **The operator's daemon** owns `~/.agent-queue/` and the database named in
  its config. A contributor's checkout writes neither.
* **The box** owns the `flock` test slots `aq test` takes; they live in a lock
  directory derived from the config, not in the checkout.

## Common failures and recovery

| Symptom | Cause | Recovery |
|---|---|---|
| `POSTGRES_TEST_DSN is not set; PostgreSQL is required by this test suite.` | No test DSN in the environment. | `docker compose up -d postgres` and export the DSN above. Nothing was run. |
| `connection refused … 5533` | The compose service is not up. | `docker compose up -d postgres`, then `docker compose ps` to confirm it is healthy. |
| `ModuleNotFoundError: agent_queue_api_client` | The generated client is not installed. | `pip install -e packages/aq-client` |
| `TS client not generated — run: ./scripts/regenerate-ts-client.sh --from-file` | Fresh checkout, no generated TS sources. | Run exactly that. |
| `openapi-python-client 0.30.x is installed but packages/aq-client/ is generated by 0.29.0` | Wrong generator version. | `pip install 'openapi-python-client==0.29.0'` — see [codegen](codegen.md#the-python-api-client). |
| `schema behind code; ask the operator to upgrade` | Something tried to migrate a database this scope may not migrate. | Stop. Report it. See [migrations](../guides/migrations.md). |
